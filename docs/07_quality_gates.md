# 07 品質閘門、獨立盲審與成品驗收

核心鐵則：**「測試通過」不等於「成品對」；「沒有錯誤訊息」不等於「東西真的有產生且人能用」。**

## 1. 工程狀態與成品狀態分開報

- **工程**：編譯、單元測試、靜態檢查、檔案範圍（`scope_check`）、證據雜湊（`evidence_record`）。
- **成品**：實際使用者看得到／跑得出來的行為、畫面、聲音、報表、公開入口端到端輸出。
- 禁止用工程 `PASS` 掩蓋成品未驗或跳過檢查；尚未驗證的項目必須寫 `NOT_TESTED` 或 `UNKNOWN`。

## 2. 獨立審查（物理唯讀 + 跨模型族）

- **盲審隔離**：實作者不得自審交件。總監於 Antigravity 中指派自訂代理 **`dw-blind-reviewer`**（YAML 已鎖定 `tools: [read_file]`，物理級無法改檔或執行指令），只提供工單規格、差異檔或盲審包，**不提供作者的自我總結或分數**。
- **跨模型族優勢**：開 Swarm 或多對話審查時，優先指定與實作者不同的模型或更高的 effort 擔任盲審，避免同源視角盲點。
- **大量閱讀隔離**：若須檢視大量輸出檔或截圖，先用短上下文 subagent 依固定清單初篩並回報具體路徑與問題，總監親自覆核標記異常項目與至少 1 份抽檢。

## 3. 常識閘門表（成品／UI／視覺類交件必附）

Worker 交件前必須逐項檢視並隨 `TASK REPORT` 附上本表；任何「看不到／沒產出」皆不通過：

| # | 檢視問題 |
|---|---|
| 1 | 方向與目的：每個元素是否朝正確方向、執行應有功能？ |
| 2 | 因果銜接：動作與結果是否合理接續？有無憑空出現、閃跳或無因突變？ |
| 3 | 全場與背景：除了主體，次要與背景元素是否合理？有無僵住、重複或消失？ |
| 4 | 形狀與比例：整體尺寸、排版比例是否自然不失真？ |
| 5 | 對稱性：一側出錯時另一側必檢；成對元素雙邊皆須回答。 |
| 6 | 破損與亂碼：有無破圖、遮擋、重疊、空白、文字截斷或編碼亂碼？ |
| 7 | 完整性：必要元素數量是否齊全（逐項點數）？ |
| 8 | 規格對齊：數值、單位、顏色、文字與規則是否與工單或規格書一致？ |
| 9 | 端到端流程：從啟動到第一個可用結果，有無卡死、順序錯或報錯？ |
| 10 | 第一印象（3 秒原則）：不看說明時，一般使用者 3 秒內是否覺得哪裡怪？ |

## 4. Antigravity 視覺與量尺工具鏈

- **瀏覽器實測（`/browser` 與 `BROWSER_HOST_FACTS`）**：前端或本機網頁作品必須由總監委派內建 **`browser` subagent**（或 `dw-visual-qa` 引導）實際開啟 `localhost` 操作互動流程、檢查 Console/Network 錯誤並截圖。總監僅採信系統宿主訊息 **`BROWSER_HOST_FACTS`** 驗證過的訪問來源與截圖路徑，不盲信子代理口頭回報。
- **量尺先行（`tools/ruler_check.py`）**：先證明量尺／日誌看得到真實資料，再判產品好壞。對到 0 筆、低於 `--expect-min`、無法對齊真實 log 行、或命中截斷計數（`--cap-key`）導致必要資料遺失，一律判 **`INVALID`**。
- **實測計畫校對（`tools/run_plan_check.py`）**：跑重測試或基準前確認每個開關、鏡頭與輸出的 `code`（`path:line`）存在目標 commit；跑完核對 log 實際啟動參數，不符整場 **`INVALID`**。
- **盲審圖包驗證（`tools/pack_check.py`）**：檢查截圖不為空、內容去重後 `unique=` 達標，且涵蓋 `required_segments` 指定關鍵區段（如起手、動作中、收尾）。
- **模擬時鐘規則**：表現層（動畫、停留、移動、渲染混合）一律使用模擬時鐘 `dt`，避免採擷負載下因牆鐘（wall clock）造成假跳動。

## 5. 修正輪數上限與獨立診斷（`tools/round_check.py`）

- 修正採「隔離分支執行 + **3 輪為一組**（1 次主修正 + 2 次有根因假設的定向修正）」。同一根因 2 輪無進展即止血重審。
- 一組（第 3 輪）未過時，進入第 4 輪前必須先產出 **`ROOT_CAUSE_STUDY.md`**（含每節開頭的 `| 項目 | 測試條件 | 參考條件 |` 表、`WHERE:`、`ALTERNATIVES:`、`DECISION:`），才開啟下一組 3 輪。換 worker **不重置輪數**。
- **第 2 組仍未過**：強制引入**獨立診斷**（不同代理或不同模型，只讀不寫），記錄 `DIAGNOSIS_BY:` 與 `DIAGNOSIS_RESULT:`；診斷者不實作、實作者照診斷修。`round_check.py` 自動把關並檢查條件表。

## 6. 裁決自檢證據

- 寫裁決的人（總監）在 `GATE_VERDICT` A 節必附至少一行自己親跑的 `- \`<指令>\` exit=<n> at=<HH:MM>`（`ran_line.py` 印出，不抄 worker 報告），否則 `gate_check.py --verdict` 依 `verdict_self_check` 印 WARN 或 FAIL。
